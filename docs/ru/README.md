# Документация grillspec

grillspec превращает запрос в прогриленный журнал решений, спек, план и
протестированный код. У каждого механизма ниже одна причина существовать и своя цена
в контексте; цена каждого скилла — в [Сколько grillspec стоит в токенах](tokens.md).

| Механизм | Страница | Зачем он нужен | Цена в контексте |
|---|---|---|---|
| Бутстрап | [Как работает бутстрап](how-it-works/bootstrap.md) | Скилл, о котором агент не знает, никогда не срабатывает. | всегда: роутер и каталог |
| Гриль | [Как работает гриль](how-it-works/grilling.md) | Дизайн на догадке стоит дороже десяти лишних вопросов. | по требованию |
| Council | [Как работает council](how-it-works/council.md) | Независимые перспективы ловят то, что пропускает одна линия рассуждений. | по требованию; внешние CLI тратят свои токены |
| Спеки | [Как работают спеки](how-it-works/specs.md) | Требования с ID сценариев связывают тесты с решениями. | по требованию |
| Память | [Как работает память](how-it-works/memory.md) | Факт, выясненный однажды, не должен выводиться заново в каждой сессии. | всегда: блок памяти |
| Планы | [Как работают планы](how-it-works/plans.md) | План хранит решения, которые исполнитель не может принять сам. | по требованию |
| Выполнение | [Как работает выполнение](how-it-works/execution.md) | Задачи test-first и свежее ревью держат код верным спеку. | по требованию |
| Память между сессиями | [Как работает память между сессиями](how-it-works/session-memory.md) | Новой сессии не нужно заново объяснять прошлую. | всегда: сводка (≤ 1 500 токенов) |
| Архив | [Как работает архив](how-it-works/archive.md) | Живые спеки остаются записью того, что делает система. | по требованию |
| Ворота между фазами | [Как работают ворота](how-it-works/gates.md) | Код, написанный до одобрения спека, — догадка. | нет: это хук, а не контекст |
| Цена в токенах | [Сколько grillspec стоит в токенах](tokens.md) | «Стоит немного» должно быть числом. | — |
