# Как работает память

После одобрения спека агент предлагает устойчивые факты, которые принесло изменение, —
как запускать тесты, соглашение, ограничение, подводный камень — и сохраняет только
те, что вы одобрили. Каждая следующая сессия в любом харнессе начинается, уже зная их.

## Где живёт память

В `AGENTS.md`, в собственном блоке:

```markdown
<!-- grillspec:memory:begin -->
## Project memory (grillspec)
- [command] Run tests with uv run pytest -q (2026-10-17-ci)
- [constraint] Never commit anything under private/ (2026-10-17-docs)
<!-- grillspec:memory:end -->
```

`AGENTS.md` загружают все пять харнессов (Claude Code и GigaCode — через строку
`@AGENTS.md`, которую `grillspec init` добавляет в `CLAUDE.md` и `GIGACODE.md`). Блок
памяти отделён от блока, которым управляет `grillspec init`: повторный `init`,
обновление grillspec или удаление его никогда не трогают.

## Что запоминается

Каждая запись должна отвечать на один вопрос: какую ошибку она предотвращает в
будущей сессии?

| Категория | Для чего |
|---|---|
| `command` | как собрать, протестировать или запустить проект |
| `convention` | правила именования, стиля, структуры |
| `constraint` | инварианты и правила «никогда не делать X» |
| `gotcha` | неочевидные подводные камни |
| `docs` | ссылка на длинный материал в `docs/grillspec/memory/<topic>.md` (глоссарий, предыстория решения) |

Никогда не сохраняются: секреты, токены, пароли, внутренние URL и персональные данные;
всё, что уже сказано в коде, конфиге или документации; статус и история изменения;
текст, скопированный из вывода инструментов или веб-страниц; личные предпочтения.

## Размер и стоимость в токенах

Не больше 40 записей по 160 символов — около 1,6k токенов в худшем случае, которые
оплачиваются в каждой сессии. Когда блок полон, агент сначала предлагает удалить
записи или перенести их в длинные документы, а потом уже добавлять новые.

## Команды

| Команда | Что делает |
|---|---|
| `grillspec memory list [--json]` | нумерованные записи и сколько из 40 занято |
| `grillspec memory add --category <c> --change <id> -- '<text>'` | добавляет одну запись; отказывает дубликатам, некорректному тексту и 41-й записи |
| `grillspec memory retire <n>` | удаляет запись n |

Запись атомарная, сохраняет права файла и проходит через символическую ссылку
`AGENTS.md`; файл перезаписывается с его основным окончанием строк. Блок можно править и вручную;
`grillspec memory` подскажет, если строка потеряла формат записи.

## Личные предпочтения

Как вам удобно работать (тон, язык, инструменты), место в вашем собственном
глобальном файле, а не в проекте. Агент показывает текст для вставки; за пределами
проекта он ничего не пишет.

| Харнесс | Глобальный файл |
|---|---|
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` |
| Antigravity | `~/.gemini/GEMINI.md` |
| GigaCode | `~/.gigacode/GIGACODE.md` (не проверено) |
| Cursor | Settings → Rules → User Rules |

## Как память остаётся актуальной

Каждая запись называет изменение, из которого пришла. Когда новый спек противоречит
записи, агент предлагает удалить или заменить её — и делает это только после вашего
ответа.

После памяти агент пишет план реализации (см.
[Как устроены планы](plans.md)).
