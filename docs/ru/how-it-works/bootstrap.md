# Как работает бутстрап

В начале каждой сессии — и снова после `/clear` или сжатия контекста — grillspec кладёт
в контекст агента три вещи:

1. тело скилла-роутера `using-grillspec`;
2. одну строку статуса, например
   `grillspec: phase=spec change=2026-10-17-login next=write the spec, grillspec validate, then approve`,
   и точную команду запуска CLI grillspec на этой машине;
3. по строке `WARNING:` на каждую найденную проблему (неизвестный ключ конфига,
   нечитаемый файл состояния, отсутствующий Python).

## Почему полный роутер

Скиллы загружаются по требованию: агент видит только короткое описание каждого и сам
решает, открывать ли его. Это дёшево — и ломается ровно тогда, когда важно: агент,
уверенный, что изменение «очевидное», так и не откроет скилл, который задал бы вопрос.
Роутер закрывает эту дыру. Он в контексте с первого сообщения, а его единственное
правило проверяемо: *если в запросе есть выбор между вариантами, выбор принадлежит
пользователю*. Дальше таблица в роутере подбирает масштаб ответа: просто сделать,
быстрый вопрос в чате или полный пайплайн.

Альтернатива — указатель в десять строк вместо полного роутера — стоит меньше токенов
и срабатывает менее надёжно. grillspec выбрал надёжность; цена — в следующем разделе.

## Сколько это стоит

Роутер — около 730 слов, примерно тысяча токенов; платится один раз за сессию и один
раз за каждое сжатие контекста. Строка статуса и предупреждения добавляют несколько
десятков. Измеренные цифры для целых сессий, с grillspec и без, появятся вместе с
бенчмарком экономики токенов.

## С другими плагинами процесса

Superpowers и похожие плагины вставляют свой роутер. Два роутера спорят за одни и те же
решения, поэтому роутер grillspec просит агента предложить вам оставить включённым
только один, а до тех пор — следовать grillspec в планировании.

## Строка статуса

Строку выдаёт `grillspec status`. Фаза вычисляется, а не хранится: нет активного
изменения → `idle`; гриль не подтверждён → `grill`; спек не утверждён → `spec`; план не утверждён → `plan`; есть
неотмеченные шаги плана → `execute`; всё отмечено → `done`. Утверждения хранятся в
`.grillspec/changes/<id>.toml`; активное изменение этого рабочего дерева — в
`.grillspec/state.json`, который git игнорирует, поэтому у каждого worktree оно своё.

## Fail-open

Хук, который падает или блокирует, утянул бы агента за собой, поэтому бутстрап не
делает ни того, ни другого:

- **Нет Python 3.11+** — раннер хуков сообщает об этом в контексте («gates are OFF»)
  средствами shell и завершается успешно; pre-tool ворота тогда пропускают любой вызов
  (см. [Как работают ворота](gates.md)).
- **Сломанный конфиг или файл состояния** — проблема становится строкой `WARNING:`;
  роутер всё равно загружается.
- **Любая другая ошибка** — сообщение «grillspec bootstrap failed: …»; сессия
  продолжается.
