# Как идёт выполнение

После одобрения плана агент выполняет его задача за задачей одним из двух
исполнителей, по TDD, и заканчивает ревью всей ветки. Эти скиллы адаптированы из
Superpowers 7.0.0 (см. `NOTICE`); grillspec переводит их на свой формат плана и на
`grillspec exec`, который одинаково работает в Linux, macOS и Windows.

## Два исполнителя

| Исполнитель | Скилл | Как | Когда рекомендуется |
|---|---|---|---|
| `subagent` | `grillspec-subagent-execution` | свежий субагент-исполнитель на каждую задачу, затем свежий ревьюер задачи, раунды исправлений до чистого ревью; финальное ревью всей ветки | задачи зависят от интерфейсов друг друга, или ошибка обойдётся дорого |
| `inline` | `grillspec-inline-execution` | агент сам выполняет все задачи, тест первым; в конце один свежий ревьюер проверяет всю ветку | задачи небольшие и независимые; также исполнитель для харнесса без субагентов |

Вы выбираете его при одобрении плана; после этого status пишет
`execute the plan with <skill>`.

## Помощники: `grillspec exec`

| Команда | Что делает |
|---|---|
| `grillspec exec workspace` | создаёт `.grillspec/exec/<change-id>/` (игнорируется git) с журналом |
| `grillspec exec start <N.M>` | пишет бриф задачи (шапка плана плюс эта задача) и печатает BASE — коммит, с которого задача начинается |
| `grillspec exec done <N.M> <BASE> -- <test command>` | запускает тесты без оболочки; только если они прошли, отмечает задачу в плане и добавляет строку в журнал |
| `grillspec exec review-package <BASE> [<HEAD>]` | пишет коммиты, статистику и diff для ревьюера; отказывает для пустого или чужого диапазона |

Так как `exec done` отмечает чекбоксы самого плана, прогресс видят и
`grillspec status`, и OpenSpec, а новая сессия продолжает с первой неотмеченной задачи.

## Журнал

`.grillspec/exec/<change-id>/progress.md` хранит то, что сессия иначе забыла бы:
выполненные задачи с диапазоном коммитов и командой тестов, каждое **решение**
(ruling: что агент решил, когда план был неоднозначен или неверен, и чего это стоит
при ошибке), раунды исправлений и отложенные замечания ревью. В финальном сообщении
исполнитель перечисляет все решения и отложенные замечания.

## Разработка через тесты

Строка `Test:` у задачи определяет её red: задачи `scenario-first` и `reproduce-first`
сначала пишут все свои тесты и один раз видят, что они падают по правильной причине, —
до любого рабочего кода; тесты `characterization` фиксируют текущее поведение перед
рефакторингом и остаются зелёными; задачи `none` — связующий код. Отладка
(`grillspec-debugging`) начинается с корневой причины, и ни задача, ни ветка не
считаются готовыми без свежего вывода проверки (`grillspec-verification`).

## Ревью и завершение

Ревью идут по `grillspec-requesting-review`; замечания агент взвешивает по
`grillspec-receiving-review`, а не соглашается рефлекторно. Когда все задачи отмечены
и финальное ревью чистое, `grillspec-finishing` предлагает способы влить ветку
(слияние, pull request, оставить как есть) и убирает worktree, созданные через
`grillspec-worktrees`. Коммиты следуют правилам проекта из `AGENTS.md`.
