# Как работает council

Во время гриля агент может спросить council о решении, прежде чем вынести его вам.
Council помогает выбрать, но не выбирает за вас. Под вариантами вы видите одну
строку: на чём сошлись участники и кто не согласен:

```
Council 3/4: A (claude, codex, simplicity) · dissent devil→B: retries hide outages · gemini: timeout
Same-model members agreeing is a weak signal.
```

В журнал решений попадает только несогласие (`· council 3/4 · dissent devil→B`), а
метаданные журнала считают запуски council (`council_calls=`).

## Участники

| Участник | Что это |
|---|---|
| `role:simplicity` | Субагент на той же модели, что и агент; ищет самый простой вариант, который полностью работает. |
| `role:devil` | Субагент, который спорит с вариантом, который выбрало бы большинство. |
| `role:risk` | Субагент, который ищет, что сломается в проде и что дорого откатывать. |
| `cli:<vendor>[@<model>]` | Агентский CLI другого вендора, который `grillspec council ask` вызывает без интерфейса. Без `@<model>` используется модель этого CLI по умолчанию. |

Роли работают на той же модели, что и агент, поэтому их согласие — слабый сигнал;
агент так и говорит. Внешние участники приносят слепые пятна других моделей.

Если `council.members` пуст, council — это три роли и каждый CLI, который
`grillspec detect --json` находит установленным и не разлогиненным, кроме
экспериментальных. Если так не нашлось ни одного CLI — например, на машине, где из
агентских CLI есть только GigaCode, — вместо них входят установленные и не
разлогиненные экспериментальные CLI, чтобы у council остался внешний участник.
`detect --json` выводит этот список в поле `council`, а `grillspec council ask` без
`--members` спрашивает его участников `cli:`.

Когда вопрос-настройка предлагает council, он называет участников и стоимость.

## Когда он запускается

| Глубина | Какие решения получают council |
|---|---|
| `quick` | никакие |
| `standard` | корневые и трудно обратимые |
| `deep` | все |

Council стартует, как только его решение можно задать, и работает в фоне, пока
агент спрашивает вас о другом. Каждому внешнему участнику даётся `council.timeout`
секунд (по умолчанию 120); не успевшие названы в вопросе, и гриль идёт без них.

## Что получает каждый вендор

Внешние участники получают один промпт через stdin и ничего больше: вопрос, его
варианты, решения, от которых он зависит, и короткую сводку фактов от агента — без
секретов. Решение лежит внутри разделителей данных со случайной меткой на каждый
вызов, поэтому текст внутри не может выдать себя за инструкцию.

| Участник | Получает | Где запускается | Инструменты |
|---|---|---|---|
| субагент-роль | тот же промпт | в сессии агента | не нужны |
| внешний CLI | промпт через stdin | новая пустая временная папка, удаляется после | его режим только чтения или планирования; у claude вообще без инструментов; без MCP-серверов (claude); без сохранения сессии (claude, codex) |
| внешний CLI с `share_project = true` | промпт через stdin | папка проекта | тот же режим, рабочая папка — ваш проект |

Только чтение — не то же самое, что нет доступа. В режимах только чтения codex,
cursor-agent, gemini, agy и gigacode всё равно могут читать файлы, доступные вашей
учётной записи, в любом месте машины; промпт просит их этого не делать, а пустая папка
лишь убирает проект с их глаз. Полностью без инструментов работает только `claude`.
Если это неприемлемо, поставьте `council.external = "never"` или оставьте только
`cli:claude`.

`grillspec council ask --dry-run` печатает каждую команду, её папку и полный промпт,
ничего не запуская.

## Как отключить внешних участников

Поставьте `council.external = "never"` в `.grillspec/config.toml` (для проекта) или в
пользовательском конфиге. Значение побеждает из любого файла: проект не может снова
включить внешних участников за вас, а вы не можете включить их в проекте, который
их запрещает. Роли продолжают работать.

## Стоимость

Запуск council — один вызов на участника. Внешние вызовы тратят вашу квоту у каждого
вендора: примерно `<решения> × <участники>` вызовов за гриль; в standard-гриле около
4 решений с council, в deep — около 15.

## Вендоры

`grillspec detect --json` сообщает про каждый CLI, установлен ли он и выполнен ли
вход. Проверка никогда не отправляет промпт.

| Вендор | Вызов без интерфейса | Проверка входа |
|---|---|---|
| `claude` | `claude -p --tools "" --strict-mcp-config --no-session-persistence --setting-sources user --output-format json` | `claude auth status` |
| `codex` | `codex exec --skip-git-repo-check -s read-only --ephemeral -` | `codex login status` |
| `cursor-agent` | `cursor-agent -p --trust --mode ask --output-format json` | `cursor-agent status --format json` |
| `gemini` | `gemini --approval-mode plan -o json -p "…"` | нет: считается ключ в `GEMINI_API_KEY` или сохранённый вход; иначе неизвестно |
| `agy` | `agy --sandbox -p "…"` | нет: неизвестно |
| `gigacode` (экспериментально) | `gigacode -e none --no-chat-recording --approval-mode plan -o json "…"` | `gigacode auth status` |

CLI без входа пропускается и называется в вопросе. CLI с неизвестным статусом
пробуется; сбой показывается как ошибка.

### GigaCode

Поддержка GigaCode экспериментальная: в council по умолчанию он входит, только когда
нет другого установленного агентского CLI со входом, а иначе запускается, только если
вы явно указали `cli:gigacode` в `council.members`. Поддержка сверена с бандлом
GigaCode 0.13.1, вживую ещё не запускалась.

- `-e none` запускает участника без расширений, чтобы он не подгрузил роутер и хуки
  самого grillspec; `--no-chat-recording` не сохраняет вызов в историю сессий.
- `gigacode auth status` всегда завершается с кодом 0: строка с `✓` считается входом,
  строка с `⚠` (на любом языке) — его отсутствием.
- Внутри GigaCode роли работают через его инструмент `agent` как встроенный субагент
  `general-purpose`.
- Если сам агент работает в GigaCode, участник `cli:gigacode` — та же модель в
  чистом контексте, и его согласие — такой же слабый сигнал, как у роли. Для второй
  модели укажите её: `members = ["role:devil", "role:risk", "cli:gigacode@<model>"]`,
  взяв модель, доступную по вашей лицензии (см. `/model` в GigaCode).

GigaCode CLI нужен Node.js 22 или 24 LTS. На Node 26 он падает с
`UND_ERR_INVALID_ARG invalid onError method`, когда установлен его корпоративный
пакет CA-сертификатов.
